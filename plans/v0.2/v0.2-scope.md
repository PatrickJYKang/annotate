# Annotate 0.2 – Scope and Phasing

Date: 2026-08-22 (rev 11 pin-animation amendment)
Status: Annotate 0.2.2 code-complete; non-English editorial review pending
Companion: [project-v2-schema-and-migration.md](project-v2-schema-and-migration.md)
Implementation: [implementation-plan.md](implementation-plan.md)

## Purpose

This document lists the set of changes that constitute version 0.2. It is the planning umbrella for the redesign discussed after the 0.1.0-pre.3 release; the companion document sketches the `project.v2` on-disk schema and the plan for migrating the application code to it.

0.2 is a breaking release with **no backwards compatibility**: it does not read, write, or convert `project.v1` folders — they are refused with a clear message, and old projects stay on 0.1 via the pinned release tag. "Migration" in the companion document means migrating the application code to the v2 model, not migrating data.

---

## The change set

### 1. Clips become the unit of analysis (data model)

- Marks and stills are removed as first-class entities. Both collapse into the clip:
  - a former **mark** is a clip-local **frame pin** (the moment you choose to annotate);
  - a former **still** is an **annotation document pinned to a frame** of a clip.
- Tags move from marks to **clips**. The tag folder tree, exports, and the presentation asset browser group and filter by clip tags.
- The annotate workflow becomes: open a clip → scrub to a moment → press **Annotate** → the annotation editor opens for that frame → saved annotations are stored under the clip.
- **Pin annotations are independent of the clip's own annotations.** A pin's annotation documents (still-style drawings for that frame) have nothing to do with the clip's keyframed/animated annotations; they are separate layers with separate storage. An explicit **pin → clip import** action (copying a pin document into the animated layer at that frame) preserves today's still-import workflow without coupling the layers.
- Pin annotation documents may own an ordered per-shape entrance sequence with appear, fade, grow, and wipe effects; on-click, with-previous, and after-previous triggers; and editable delay/duration. This sequence is used by pin-editor preview, clip pause playback, and direct pin slides, but is not copied into the clip's position-keyframe layer.
- **Presentations: the default slide unit is the clip.** Pins act as automatic pause points during clip playback (play → pause at pin → show the pin's annotations → resume); each slide can deselect pins it does not want to pause on. Using a pin directly as a slide remains possible, but it is the secondary path, not the default. Authoring can open a referenced clip in a separate editor tab and refreshes when that clip is saved.

### 2. Frames replace milliseconds

- All stored and app-level **media positions** become integer frame indices. The video element and ms-based sidecar/cache APIs are explicit conversion boundaries; presentation wall-clock durations such as holds and cue timing remain milliseconds. Match-video trims become frame offsets because they select source media positions.
- Frame indices are relative to the owning video's stored FPS. FPS, `frameCount`, width, and height are per-video rather than project-wide, so mixed media can coexist and resolve independently in presentations. A v2 import must receive authoritative metadata from import/probe and fails rather than estimating frame count from browser duration.
- Details and conversion rules in the companion schema document.

### 3. Tagging window (replaces pause → menu)

- A persistent tagging panel with buttons, in the style of a Sportscode code window, defined by a per-project **`tagging-board.json`**.
- **`tagging-schema.yaml` is replaced, not extended.** The v1 schema modeled a dropdown tree; the v2 artifact models a button board, and JSON fits the structure better than YAML. The board defines the tag vocabulary directly (buttons carry tag identity; toggles carry facets); the tag folder tree view derives its grouping from the board.
- **Middle-path semantics** (adopted per plan review; vetoable): the board stays flat (deep tree nesting is not ported), but per-button facet applicability (`facetGroupIds`) and conditional facet groups (`requiresAny`, e.g. goal-method-requires-goal) **are** ported from the YAML — they are user-authored semantics, not tree structure. Re-tagging prunes inapplicable facets instead of v1's clear-all. Boards are mandatory: a v2 project auto-installs the default board when missing.
- The board is a fixed coordinate surface: board dimensions, group-label rectangles, button rectangles, and modifier slots define a stable layout that does not require navigating menus. Every primary button is an exact-frame start/stop range toggle with no automatic pre/post-roll. Different buttons may remain active together, so captures can overlap.
- The tagging timeline derives one lane per board group, includes active captures before they close, defaults to a one-minute viewport, and supports horizontal zoom/scroll with a five-second manual-scroll override of playhead auto-follow.
- Replaces `TaggingMenu` and the pause → context-menu flow entirely.

### 4. Hierarchy: Analysis ∥ Presentations (UI and disk)

- The project dashboard presents two parallel wings: **Analysis** (videos → clips) and **Presentations**. Neither is downstream of the other in navigation; analysis stays video-scoped inside its wing.
- On disk, analysis data moves under `analysis/`, so the layout states the hierarchy: `media/` | `analysis/` | `presentations/`. Each clip is a **self-contained folder** (`analysis/clips/<clipId>/` holding `clip.json` and that clip's pin-annotation documents) — see the companion doc for the under-clip vs parallel-tree trade-off.
- Deletion is recoverable: clip/pin/document data is copied and verified in project-local `.trash/` before source removal. Presentations degrade to a visible missing state rather than blocking deletion.
- Exports remain renders/reports written under `exports/`; the current UI writes clip JSON/CSV plus annotated pin PNGs. Source media is referenced, never copied into export folders. Presentation motion plays directly from absolute frame ranges in the original project videos. Dormant exact-motion infrastructure remains available only for possible future exports.

### 5. Panelization

- The workspace screens that benefit from simultaneous surfaces use resizable panels (Photoshop-docked, not windowed): dashboard, player, clip editor, and presentation authoring. Splitter sizes persist per route. Metadata forms and full-screen present mode intentionally remain ordinary layouts.
- `react-resizable-panels` is the panel dependency. The clip editor owns viewer/inspector/timeline regions; the player owns video/board/tree regions; presentation authoring owns browser/canvas/storyboard/inspector regions. Its clip preview reuses the frame-native clip timeline in a pins-only mode, while full-screen present mode remains free of editor transport chrome.
- Interactive rearranging of panel positions remains out of scope for 0.2.

### 6. Deletions

The redesign removes:

- `/stills` page, still capture, thumbnail management
- mark machinery (`marks[]`, mark pinning, `sourceMarkId` integrity repairs — replaced by v2 integrity checks)
- `TaggingMenu` and the `/dropdown-test` sandbox
- `/player-legacy`
- experimental foreground segmentation, its `/segmentation-test` sandbox, and the `/segment` sidecar API

### 7. Internationalization — implemented last

- English, French, Spanish, and Simplified Chinese (`zh-CN`) use a light client-side `t()` layer with one persisted locale toggle and no URL-locale routing.
- String extraction landed after structural screen work. All four catalogs have 555 aligned keys and interpolation tokens; CJK font/wrapping/layout support is in place.
- Native-speaker editorial review of French, Spanish, and Simplified Chinese remains the open manual sign-off.

### 8. Quick annotate — isolated, best-effort only

- `/quick-annotate` stays for now: own route, OPFS-backed, no shared state. It is not deepened into the new model and it is **not a compatibility promise**: it rides the phase-0 annotation-payload refactor for free, but if preserving its `annotations.v1` documents complicates the v2 boundary at any point, it is deleted without ceremony. Long-term it is a candidate for extraction into a separate repo/deployment.

### 9. Dependency trim — complete

- Browser-side TensorFlow/TFJS, sidecar TensorFlow/Keras/Kornia, foreground-segmentation code, and unrelated development-only runtime packages are removed. The sidecar has separate runtime and development locks, while tracking and mandatory PnLCalib homography remain fully installed.
- On the release-verification Mac, a clean web install contains 374 packages and occupies approximately 482 MB. The clean sidecar runtime contains 53 packages and occupies approximately 976 MB, down from roughly 2.4 GB before the trim. PnLCalib source and weights remain a separate required download.

## Explicitly deferred (not 0.2)

- Windowed/floating UI inside the 0.2 browser application. This was rejected for the 0.2 panelization scope. The 0.2.2 browser gate and user-guide synchronization are now complete; a later Electron host may intentionally map browser tabs and selected panels to native windows without changing the shared project model. See [Desktop application direction](../desktop-application-direction.md).
- Drag-to-rearrange panel docking (design for it, don't build it).
- Any `project.v1` support at all — read, write, or data migration. Old projects stay on 0.1 (pinned release tag).

## Phasing

This table records the implemented order; temporary `/v2` routes and the v1 coexistence window no longer exist in the canonical application.

| Phase | State | Work |
|---|---|---|
| 0 | Complete | Schema lock, frames/types/storage, repository/trash, shared payload/renderer, authoritative frame count |
| 1 | Complete | Parallel v2 vertical slice, browser coverage, canonical flip, and v1 deletion sweep |
| 2 | Complete | Tagging board and tag-to-clip capture workflow |
| 3 | Complete | Analysis/Presentations hierarchy and navigation/handle restoration |
| 4 | Complete | Persisted resizable workspace panels |

Every code phase landed green. During phase 1, v1 specs continued running until the flip while v2 specs accumulated alongside; browser coverage did not drop during the replacement.

## Adopted board decision

The implemented middle path is flat board groups plus `facetGroupIds` applicability and `requiresAny`; deep primary-tree nesting is dropped. This was the designated vetoable decision before schema lock. Changing it now is an explicit schema amendment rather than an implementation-plan toggle.

## Settled decisions

- Every primary tag button is an exact-frame start/stop range toggle. Range capture snapshots applicable facets when armed, supports overlapping active buttons, and applies modifier changes to the active range.
- Exports are renders/reports and never copy source media; a share-project bundle is outside 0.2.
- English, French, Spanish, and Simplified Chinese are the current UI locales. The editable default board remains English project data rather than a translated application catalog.
- `/player-legacy` and `/dropdown-test` are deleted.
- Annotation documents live under each clip folder. Clip-local orphans are still possible after an interrupted multi-file operation and are reported by integrity; there is no parallel project-wide annotation index.
- Absolute frames, displayed-frame conversion, half-open sidecar bounds, immutable pin frames, clip-wide annotation ids, overlapping-clip pin independence, copy/verify/delete trash, field-owned single-writer clip mutations, mandatory boards, authoritative frame counts, presentation playback/timebase contracts, and the now-retired v1/v2 coexistence boundary are locked or recorded in companion schema section 1a.

## Risks

- **No-data-migration stance**: anyone with a meaningful 0.1 project keeps it on 0.1; nothing carries forward. Accepted deliberately — pre-release install base, and a correct migrator would cost more than the data it would save.
- **Browser filesystem operations are not transactional**: local-directory move is unavailable and multi-file pin/clip operations can be interrupted. Mitigation: verified copy-before-delete, operation records/tombstones, field locks, deterministic write ordering, trash recovery, and open-time integrity reporting.
- **Sidecar availability and install weight**: v2 import requires authoritative probing, and the remaining tracking/homography stack is still substantial even after removing segmentation and splitting development dependencies from runtime. Mitigation: compatible MP4s are preserved, compatible streams are remuxed, transcode is fallback-only, dependencies are locked, and import failure is atomic. PnLCalib is a required 0.2 provider and the release launcher refuses an invalid installation; tracking and homography may remain idle during ordinary authoring.
- **Frame-boundary regressions**: project positions are frames while the sidecar remains milliseconds. Mitigation: one frame-math module, branded storage-boundary types, inclusive-sampler contract tests, non-zero-start browser fixtures, and absolute source ranges applied directly to original media during presentation playback.
- **Large editor surfaces**: `Editor.tsx`, `ClipEditor.tsx`, and presentation authoring still concentrate behavior. Panel-shell extraction reduced layout pressure without rewriting working state. Their focused unit/e2e coverage is the guard until further decomposition is worth the regression risk.
- **Contract regressions the mocks can't see**: Playwright mocks the sidecar, so wrong frame↔ms requests could pass silently. Mitigation: the contract test matrix (implementation plan Appendix D) — boundary assertions inside the mocks, non-zero `startFrame` fixtures, timebase mapping and pause-machine unit coverage. One real-sidecar smoke path verifies preserve/remux strategy selection, authoritative metadata, and sparse-sampler bounds.
- **Non-English copy quality**: catalog parity and layouts are automated, but naturalness is not. Native-speaker editorial review of French, Spanish, and Simplified Chinese remains a release sign-off rather than being overstated as complete.
