# Annotate 0.2 – Scope and Phasing

Date: 2026-07-11 (rev 6 per-video media amendment)
Status: Code-complete; native zh-CN review pending
Companion: [project-v2-schema-and-migration.md](project-v2-schema-and-migration.md)
Implementation: [implementation-plan.md](implementation-plan.md)

## Purpose

This document lists the set of changes that constitute version 0.2. It is the
planning umbrella for the redesign discussed after the 0.1.0-pre.3 release;
the companion document sketches the `project.v2` on-disk schema and the plan
for migrating the application code to it.

0.2 is a breaking release with **no backwards compatibility**: it does not
read, write, or convert `project.v1` folders — they are refused with a clear
message, and old projects stay on 0.1 via the pinned release tag.
"Migration" in the companion document means migrating the application code
to the v2 model, not migrating data.

---

## The change set

### 1. Clips become the unit of analysis (data model)

- Marks and stills are removed as first-class entities. Both collapse into
  the clip:
  - a former **mark** is a clip-local **frame pin** (the moment you choose to
    annotate);
  - a former **still** is an **annotation document pinned to a frame** of a
    clip.
- Tags move from marks to **clips**. The tag folder tree, exports, and the
  presentation asset browser group and filter by clip tags.
- The annotate workflow becomes: open a clip → scrub to a moment → press
  **Annotate** → the annotation editor opens for that frame → saved
  annotations are stored under the clip.
- **Pin annotations are independent of the clip's own annotations.** A pin's
  annotation documents (still-style drawings for that frame) have nothing to
  do with the clip's keyframed/animated annotations; they are separate
  layers with separate storage. An explicit **pin → clip import** action
  (copying a pin document into the animated layer at that frame) preserves
  today's still-import workflow without coupling the layers.
- **Presentations: the default slide unit is the clip.** Pins act as
  automatic pause points during clip playback (play → pause at pin → show
  the pin's annotations → resume); each slide can deselect pins it does not
  want to pause on. Using a pin directly as a slide remains possible, but it
  is the secondary path, not the default.

### 2. Frames replace milliseconds

- All stored and app-level **media positions** become integer frame
  indices. The video element and ms-based sidecar/cache APIs are explicit
  conversion boundaries; presentation wall-clock durations such as holds
  and cue timing remain milliseconds. Match-video trims become frame
  offsets because they select source media positions.
- Frame indices are relative to the owning video's stored FPS. FPS,
  `frameCount`, width, and height are per-video rather than project-wide, so
  mixed media can coexist and resolve independently in presentations. A v2
  import must receive authoritative metadata from import/probe and fails
  rather than estimating frame count from browser duration.
- Details and conversion rules in the companion schema document.

### 3. Tagging window (replaces pause → menu)

- A persistent tagging panel with buttons, in the style of a Sportscode code
  window, defined by a per-project **`tagging-board.json`**.
- **`tagging-schema.yaml` is replaced, not extended.** The v1 schema modeled
  a dropdown tree; the v2 artifact models a button board, and JSON fits the
  structure better than YAML. The board defines the tag vocabulary directly
  (buttons carry tag identity; toggles carry facets); the tag folder tree
  view derives its grouping from the board.
- **Middle-path semantics** (adopted per plan review; vetoable): the board
  stays flat (deep tree nesting is not ported), but per-button facet
  applicability (`facetGroupIds`) and conditional facet groups
  (`requiresAny`, e.g. goal-method-requires-goal) **are** ported from the
  YAML — they are user-authored semantics, not tree structure. Re-tagging
  prunes inapplicable facets instead of v1's clear-all. Boards are
  mandatory: a v2 project auto-installs the default board when missing.
- Pressing a tag button creates a tagged clip around the current playhead
  (lead/lag), and/or press-to-start / press-to-stop range capture — see open
  decisions. Buttons carry per-button `hotkey`, `leadSeconds`, `lagSeconds`,
  and `mode`; the capture boundary converts durations through the selected
  video's FPS.
- Replaces `TaggingMenu` and the pause → context-menu flow entirely.

### 4. Hierarchy: Analysis ∥ Presentations (UI and disk)

- The project dashboard presents two parallel wings: **Analysis**
  (videos → clips) and **Presentations**. Neither is downstream of the other
  in navigation; analysis stays video-scoped inside its wing.
- On disk, analysis data moves under `analysis/`, so the layout states the
  hierarchy: `media/` | `analysis/` | `presentations/`. Each clip is a
  **self-contained folder** (`analysis/clips/<clipId>/` holding `clip.json`
  and that clip's pin-annotation documents) — see the companion doc for the
  under-clip vs parallel-tree trade-off.
- Deletion is recoverable: clip/pin/document data is copied and verified in
  project-local `.trash/` before source removal. Presentations degrade to a
  visible missing state rather than blocking deletion.
- Exports remain renders/reports written under `exports/`; the current UI
  writes clip JSON/CSV plus annotated pin PNGs. Source media is referenced,
  never copied into export folders. Presentation motion lives in the
  regenerable `derived-media/` cache rather than `exports/`.

### 5. Panelization

- The workspace screens that benefit from simultaneous surfaces use resizable
  panels (Photoshop-docked, not windowed): dashboard, player, clip editor, and
  presentation authoring. Splitter sizes persist per route. Metadata forms and
  full-screen present mode intentionally remain ordinary layouts.
- `react-resizable-panels` is the panel dependency. The clip editor owns
  viewer/inspector/timeline regions; the player owns video/board/tree regions;
  presentation authoring owns browser/canvas/deck/inspector regions.
- Interactive rearranging of panel positions remains out of scope for 0.2.

### 6. Deletions

The redesign removes:

- `/stills` page, still capture, thumbnail management
- mark machinery (`marks[]`, mark pinning, `sourceMarkId` integrity repairs —
  replaced by v2 integrity checks)
- `TaggingMenu` and the `/dropdown-test` sandbox
- `/player-legacy`

### 7. Internationalization — implemented last

- English and Simplified Chinese (`zh-CN`) use a light client-side `t()` layer
  with one persisted locale toggle and no URL-locale routing.
- String extraction landed after structural screen work. Both catalogs have
  512 aligned keys and interpolation tokens; CJK font/wrapping/layout support
  is in place.
- Native-speaker review of the Chinese copy remains the only open manual
  sign-off. Other languages remain post-0.2.

### 8. Quick annotate — isolated, best-effort only

- `/quick-annotate` stays for now: own route, OPFS-backed, no shared state.
  It is not deepened into the new model and it is **not a compatibility
  promise**: it rides the phase-0 annotation-payload refactor for free, but
  if preserving its `annotations.v1` documents complicates the v2 boundary
  at any point, it is deleted without ceremony. Long-term it is a candidate
  for extraction into a separate repo/deployment.

## Explicitly deferred (not 0.2)

- **Dependency trim.** Install time is dominated by the sidecar's CV stack
  (PyTorch, TensorFlow, OpenCV, Ultralytics) plus webapp TensorFlow.js.
  Acknowledged as too heavy; deliberately parked to keep building. Revisit as
  a 0.3 candidate (ideas: optional extras split for the sidecar, lazy model
  installs, dropping browser-side ML occlusion if the sidecar path is
  sufficient). The 0.2 deletions may drop a few incidental packages; take
  those opportunistically, don't chase them.
- Windowed/floating UI (rejected, not just deferred).
- Drag-to-rearrange panel docking (design for it, don't build it).
- Any `project.v1` support at all — read, write, or data migration. Old
  projects stay on 0.1 (pinned release tag).

## Phasing

This table records the implemented order; temporary `/v2` routes and the v1
coexistence window no longer exist in the canonical application.

| Phase | State | Work |
|---|---|---|
| 0 | Complete | Schema lock, frames/types/storage, repository/trash, shared payload/renderer, authoritative frame count |
| 1 | Complete | Parallel v2 vertical slice, browser coverage, canonical flip, and v1 deletion sweep |
| 2 | Complete | Tagging board and tag-to-clip capture workflow |
| 3 | Complete | Analysis/Presentations hierarchy and navigation/handle restoration |
| 4 | Complete | Persisted resizable workspace panels |
| 5 | Code-complete | Locale mechanism, full extraction, zh-CN catalog, CJK layout, and e2e; native review pending |

Every code phase landed green. During phase 1, v1 specs continued running
until the flip while v2 specs accumulated alongside; browser coverage did not
drop during the replacement.

## Adopted board decision

The implemented middle path is flat board groups plus `facetGroupIds`
applicability and `requiresAny`; deep primary-tree nesting is dropped. This was
the designated vetoable decision before schema lock. Changing it now is an
explicit schema amendment rather than an implementation-plan toggle.

## Settled decisions

- Tag buttons support per-button `instant` and `range` modes; default is
  instant. Range capture snapshots applicable facets when armed.
- Exports are renders/reports and never copy source media; a share-project
  bundle is outside 0.2.
- zh-CN is the only 0.2 translation target and the editable default board
  ships in English. zh-TW is later.
- `/player-legacy` and `/dropdown-test` are deleted.
- Annotation documents live under each clip folder. Clip-local orphans are
  still possible after an interrupted multi-file operation and are reported
  by integrity; there is no parallel project-wide annotation index.
- Absolute frames, displayed-frame conversion, half-open sidecar bounds,
  immutable pin frames, clip-wide annotation ids, overlapping-clip pin
  independence, copy/verify/delete trash, field-owned single-writer clip
  mutations, mandatory boards, authoritative frame counts, presentation
  playback/timebase contracts, and the now-retired v1/v2 coexistence boundary
  are locked or recorded in companion schema section 1a.

## Risks

- **No-data-migration stance**: anyone with a meaningful 0.1 project keeps
  it on 0.1; nothing carries forward. Accepted deliberately — pre-release
  install base, and a correct migrator would cost more than the data it
  would save.
- **Browser filesystem operations are not transactional**: local-directory
  move is unavailable and multi-file pin/clip operations can be interrupted.
  Mitigation: verified copy-before-delete, operation records/tombstones,
  field locks, deterministic write ordering, trash recovery, and open-time
  integrity reporting.
- **Sidecar availability and install weight**: v2 import requires authoritative
  probing, and CV/provider packages are large. Mitigation: compatible MP4s are
  preserved, compatible streams are remuxed, transcode is fallback-only,
  dependencies are locked, and import failure is atomic. CV can be unavailable
  after media exists without blocking ordinary authoring.
- **Frame-boundary regressions**: project positions are frames while the
  sidecar remains milliseconds. Mitigation: one frame-math module, branded
  storage-boundary types, inclusive-sampler contract tests, non-zero-start
  browser fixtures, and absolute source ranges on prepared media.
- **Large editor surfaces**: `Editor.tsx`, `ClipEditor.tsx`, and presentation
  authoring still concentrate behavior. Panel-shell extraction reduced layout
  pressure without rewriting working state. Their focused unit/e2e coverage is
  the guard until further decomposition is worth the regression risk.
- **Contract regressions the mocks can't see**: Playwright mocks the
  sidecar, so wrong frame↔ms requests could pass silently. Mitigation: the
  contract test matrix (implementation plan Appendix D) — boundary
  assertions inside the mocks, non-zero `startFrame` fixtures, timebase
  mapping and pause-machine unit coverage. One real-sidecar smoke path
  verifies preserve/remux strategy selection, authoritative metadata, and
  sparse-sampler bounds.
- **Chinese copy quality**: catalog parity and layouts are automated, but
  naturalness is not. Native-speaker review remains a release sign-off rather
  than being overstated as complete.
