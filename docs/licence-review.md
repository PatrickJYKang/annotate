# Distribution licence review

Reviewed 2026-10-24 for the local 0.2.3-rc.1 builds; updated 2026-11-01 with the completed Microsoft runtime inventory, GEOS sources and controlled Windows media candidate. This is an engineering inventory and release-gate assessment, not legal advice. PnLCalib's code-version and weight-permission questions and the Microsoft installation/file-scope review are resolved. Annotate's own licence has not changed. The remaining handoff is matching source packaging, Windows execution/replacement validation and final signed-package checks, not another request to change the project's licence. Current public installers and original staging runtimes are unchanged.

Source-status review, 2026-11-24: the implemented compliance work is committed through `ed70920`, alongside the [0.2.4 application changes](../desktop/releases/0.2.4.md). No final 0.2.4 package/source pair has been produced by this documentation pass. The dated native-binary evidence below still applies only to those inspected artifacts; current application tests do not replace the remaining Windows or final-package checks.

## Required decisions before public release

1. Carry the verified candidate PnLCalib notices and renderer cleanup into final packages. The permission questions themselves are closed; the retained public evidence is in [the enquiry record](pnlcalib-licence-enquiry.md).
2. Execute the documented source-accompanying-download approach for the integrated GPL/AGPL stack, obtaining qualified advice on unresolved scope if needed. No project licence change or process-boundary exemption is assumed.
3. Generate the corresponding-source package for the exact final binaries, and validate the source-built Windows FFmpeg candidate on Windows before replacing Gyan. The Microsoft inventory/notice/terms check is implemented; subsequent dependency changes must pass it again rather than inheriting this review silently.
4. Keep the target-specific inventory, licence texts, source archive, build recipe, version, commit and checksums alongside release artifacts. A successful build or notarization does not close these licence gates.

The current build scripts still produce local evaluation artifacts for the maintainer's testing. They do not upload them. This is not a statement that calling a publicly shared binary a preview exempts it from licence obligations.

The 2026-11-01 follow-up built and source-verified the controlled Windows media tools and passed all 86 desktop tests. A read-only, double-click Windows media comparison bundle is ready; native Windows results are still pending. No further Microsoft purchase/installation or PnLCalib correspondence is requested. Native test results and a clean matching release source snapshot must precede adoption/publication.

`npm run prepare:compliance -- <target>` produces separate review evidence without overwriting shared installers. The 2026-10-29 isolated candidates had 87 package records on macOS and 88 on Windows with no missing package notice files, conservatively including installed browser build inputs. GEOS and Shapely source recipes have since been added; the source-built Windows candidate carries its own media inputs. Historical 316/46-input collections apply to the old binary stacks, not the current Mac candidate. The 2026-10-29 pass had 77 passing desktop tests, 468 web tests, 104 sidecar tests and 26 production-renderer browser tests, plus actual Mac decode/detection/homography/export and packaged Electron smoke checks. See [implementation and remaining gates](distribution-compliance.md) for current verification. Old packages do not become compliant merely because the documentation or build scripts changed.
