# Annotate 0.2.4 Development Status

Updated: 2026-11-24. These are unreleased changes on `main`, through source commit `ed70920`, not notes for a newly built or published installer. The root/webapp manifests still use `0.2.3-rc.1`. GitHub continues to serve the unsigned `0.2.2-desktop.2` evaluation packages. Set the new candidate version before building and publishing; do not move an existing release tag. See [versioning](../../docs/versioning.md).

## Product changes

- Match setup and metadata can search OpenFootball fixtures for the supported top-five leagues and import confirmed StatsBomb Open Data lineups where available. Conflicting teams/date can be overwritten with confirmation. Existing rosters follow their matching clubs; pasted two-team lineups and CSV/TSV remain alternatives.
- Tracking accepts a manual foot-point seed when detection misses a player. One process-local all-player pass is reused across highlight selections within a clip; cached playback is paced at approximately 3x. An isolated target can bridge up to ten consecutive missing samples when its return is unambiguous. Interactive tracking remains one highlight at a time.
- Annotation text entry supports multiple lines, explicit commit/cancel keys and reopening existing text for editing.
- Clip recordings save multiple named takes with independently chosen inclusive first/last frames and recorded pin holds/animation clicks. Takes do not trim the source clip. A preview timeline, draggable bounds and frame-stepping handles support range setup before recording.
- Presentation recordings save separate deck passes. A clip take can be copied into a clip slide as range and cue data, not as a rendered video; those timings play automatically during a deck recording.
- Saved takes replay against current clip and pin annotations and export silent MP4s into `exports/recordings/`. Presentation take slide order and transitions are retained, but neither kind of take freezes the referenced drawings or source media.
- The recording/presentation viewer fits source video and annotation layers to the same aspect-ratio area. Presented-frame mapping and seek completion keep the animated overlay synchronized during playback and manual seeking.

The earlier candidate's native preferences, recovery prompts, Help-menu diagnostics and reviewed tutorial fixes remain included. Later source also includes licence/source access, updated PnLCalib notices and controlled native dependency build work; [0.2.3-rc.1 notes](0.2.3-rc.1.md) and the [compliance record](../../docs/distribution-compliance.md) retain their dated evidence.

## Data and output

Project formats stay `project.v2`, `clip.v2`, `annotations.v2` and presentation schema `2`. Recordings and slide timing/range fields are optional extensions, so existing projects need no migration when opened in current source. This does not guarantee safe editing with an older binary that discards unknown optional fields; keep a backup before downgrading.

MP4 export renders frames rather than capturing the screen. It includes no original audio, microphone, pointer or editor controls. The first non-title source determines output FPS and even-sized dimensions; other videos are letterboxed. Title-only takes use 1280 x 720 at 30 fps. The same named take/ID exports to the same file again. There is no take rename/delete/timing editor in the UI yet, and edited or missing references can change or invalidate a saved take.
